# Регламент эскалации инцидентов

Документ: `IT-эскалация.md`  
Владелец: Service Desk

## Приоритеты

| Приоритет | Пример | Реакция |
|-----------|--------|---------|
| P1 | Недоступна почта/VPN у всех | 15 минут |
| P2 | Не работает система у отдела | 1 час |
| P3 | Проблема одного пользователя | 4 часа |
| P4 | Консультация / улучшение | 1 рабочий день |

## Когда эскалировать

- Нет ответа по SLA.
- Массовый сбой.
- Подозрение на инцидент ИБ.

Эскалация фиксируется сменой статуса тикета на `escalated` и уведомлением дежурного инженера.
